## 安装与启动

### 1. 编译

```bash
go build -o oaiprism.exe ./cmd/oaiprism
```

Dashboard 的构建产物 `web/dist` 已随仓库提供；修改前端后执行 `cd web && pnpm install && pnpm build`。

### 2. 准备账号凭据

```bash
# 浏览器开发者工具里复制 prism.openai.com 的整串 Cookie：
./oaiprism.exe import -cookie "prism_oai_access_token=eyJ...; prism_session_token=..." -id main

# 或者只给 access token（Prism 的 JWT，约 10 天有效）：
./oaiprism.exe import -access-token "eyJhbGci..." -id main

# 有 refresh_token 最省心（可自动续期）：
./oaiprism.exe import -refresh-token "rt.1..." -id main

# 从标准输入读取，避免进入 shell 历史：
./oaiprism.exe import -stdin -id main
```

`import` 会在线校验凭据、补全 email / plan / account_id、尽可能换取 refresh_token，
然后写入 `secrets/accounts.json`（`0600` 权限）；网关已经在用 `secrets/accounts.db` 时直接写进数据库
（同 ID 覆盖凭据，控制台里设的名称、标签、并发上限保留），运行中在控制台点「重载并刷新」即生效。
也可以启动后在 Dashboard「账号与计划池」页走**官方 OAuth 授权导入**，或拖入账号文件直接导入。

账号以 SQLite（`secrets/accounts.db`）为准：控制台的导入与编辑、续期轮换后的令牌都只写在这里。
凭据文件 `accounts.json` 与配置里的 `creds.accounts` 只在数据库为空时导入一次，之后改它们不再生效
（文件里的令牌往往早已作废，按它重建会把好令牌换掉）；没有 SQLite 时才按文件热加载。

Dashboard 的「导入」也接受账号 JSON：单个对象、数组、`{"accounts":[…]}`，以及 sub2api 一类网关
导出的账号文件（凭据在嵌套的 `credentials` 里）。字段名不分大小写与下划线；没有任何凭据的条目会被拒绝；
同一个号再导一次会覆盖原账号。导出方的并发设置不照搬，沿用本网关的默认值（2）。

OAuth 账号续期后，新的 access_token / refresh_token 会立即写回 `secrets/accounts.db`（refresh_token
每次续期都会轮换，旧的立即作废）。同一个号不要同时放在两个网关里续期 —— 先续期的一方会让另一方的
refresh_token 作废。

> Prism 用的是自家 cookie（`prism_oai_access_token` / `prism_session_token`），
> 不是 next-auth 的 `__Secure-next-auth.session-token`。

### 3. 启动

只有一个进程：网关（8787）。出站直连 `prism.openai.com`，内置 Chrome 的 TLS 指纹，
写请求需要的 Sentinel 令牌在进程内纯 Go 签发 —— 不需要 Node.js、Chrome 或任何附属服务。

```powershell
tools\start.ps1             # 一键启动（已在运行则跳过；没有二进制就先构建）
tools\start.ps1 -Rebuild    # 从源码重新构建并重启
tools\stop.ps1              # 停止
```

手动启动（任何平台）：

```bash
cp configs/config.example.yaml configs/config.yaml
./oaiprism.exe serve -config configs/config.yaml
```

日志：脚本启动时在 `%TEMP%\oaiprism_8787.log`。

签发器自检（只连 `sentinel.openai.com`，不用账号、不碰额度）：

```bash
./oaiprism.exe sentinel -config configs/config.yaml -n 3
```

每个 token 应显示 `字段 p,t,c,flow` 且 `dx 完整执行`。

> 完全离线调试可把 `upstream.base_url` 指向 `tools/mock_upstream.py`（非 Prism 的上游走标准库，不签 Sentinel）。
> 没配凭据也能启动，`/readyz` 会返回 503 提示。

| 端口 | 服务 | 说明 |
|---|---|---|
| **8787** | 网关 `oaiprism serve` | 唯一入口（API + Dashboard + 探针）；出站直连 Prism |

#### 浏览器指纹

签 Sentinel 令牌时网关要"扮演"一台浏览器。默认用内置的通用 Windows Chrome 指纹；
想沿用自己电脑的指纹，用 `upstream.sentinel_profile` 指向一份快照（JSON，形状同
`internal/sentinel/profile_default.json`，放在 `secrets/` 下）。User-Agent、`sec-ch-ua`、
`Accept-Language` 等出站请求头、以及 TLS 握手都会自动与指纹保持一致。

指纹是某个时刻的快照，Chrome 大约每 4 周升一个大版本。网关启动时会检查：指纹落后本机
Chrome 3 个大版本以上、或（本机没装 Chrome 时）采集已超过 120 天，就在日志里提醒。用
`oaiprism profile` 查看与更新：

```bash
./oaiprism.exe profile
```

看指纹版本、本机 Chrome 版本、TLS 模板、是否过时。

```bash
./oaiprism.exe profile -capture
```

完整重新采集：在本机起一个临时页面、用你平时的 Chrome 打开（不是自动化浏览器，不需要
Node.js / Playwright），页面把 Sentinel 能读到的浏览器环境发回网关；同时让 Chrome 向本机握手
一次，比对网关的 TLS 握手，并记下 Chrome 当前的信任锚列表（随根证书库更新而变）。采集时请
把页面切到前台。

```bash
./oaiprism.exe profile -bump
```

只把版本号改成本机 Chrome 的（`-chrome 157.0.7512.80` 可手动指定），不开浏览器；品牌列表按
Chrome 自己的算法重排。

写入的文件默认是配置里的 `upstream.sentinel_profile`（没配则 `secrets/sentinel_profile.json`），
旧文件留作 `.bak`；重启网关后生效。

## 鉴权与 API Key

**有效 Key = 配置文件 `facade.api_keys` ∪ Dashboard 生成的 Key（存于 SQLite）。**

| 场景 | 行为 |
|---|---|
| 两者都为空 | 只放行**本机**请求（对端为回环地址，且 `Host` 是 localhost 或 IP 字面量） |
| 存在任意 Key | 所有接口都必须带有效 Key（`Authorization: Bearer`、`x-api-key` 或 `api-key` 头） |
| 豁免 | `/healthz`、`/readyz`、`/metrics`、`/dashboard/` 静态资源、`/admin/login`、OAuth 回调 |

首次启动时没有任何 Key，打开 `http://127.0.0.1:8787/dashboard/`，在右上角「API 密钥」里生成一个
（生成后自动保存到本浏览器）。

管理端（`/admin/*`）权限更高，满足其一即可：

1. **本机请求** + 任一有效 Key；
2. 配置文件 `facade.api_keys` 中的 Key（运维显式下发，可远程管理）；
3. 管理员登录令牌：配置 `server.admin_password`（或环境变量 `OAI_PRISM_ADMIN_PASSWORD`）后，
   `POST /admin/login` 签发 12 小时有效的会话令牌。未配置密码时不开放密码登录。

Dashboard 生成的普通 Key **只能调用 API**，远程持有者不能管理账号或签发 Key。
管理端写操作会校验 `Origin`，挡住浏览器跨站请求。

Key 由 `crypto/rand` 生成（`sk-prism-` + 32 位十六进制），签发与注销即时生效。
会话状态按 Key 的指纹隔离：不同 Key 的调用方即使会话标识相同也互不可见。

> 早期版本会自动种入固定 Key `sk-prism-live-master`，它写在源码里、等于公开。
> 若仍在使用，网关启动时会告警：请生成新 Key、更新客户端配置后注销它。

## 接入客户端

**OpenAI SDK**

```bash
export OPENAI_BASE_URL=http://127.0.0.1:8787/v1
export OPENAI_API_KEY=<你的 Key>
```

**Anthropic SDK / Claude Code**

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:8787
export ANTHROPIC_API_KEY=<你的 Key>      # SDK
export ANTHROPIC_AUTH_TOKEN=<你的 Key>   # Claude Code（走 Bearer，免去它对 API Key 的确认）
```

模型表（`facade.models`）里没有的模型名，例如 Claude Code 发的 `claude-sonnet-4-5`，在 Anthropic 接口上一律
换成默认模型。回给客户端的仍是它请求的名字，Claude Code 不用额外配置模型。

Claude Code 走**工具桥**（与 Codex 同一思路，见[架构与原理](架构与原理.md#claude-code-工具桥)）：上游负责
思考，Claude Code 的工具（Bash / PowerShell、Read、Write、Edit、Glob、Grep、子代理……）在本机执行，文件
写在你的工作目录里，权限确认照常弹出。声明了工具的 Anthropic 客户端都走这条路（`tool_choice` 为 `none`
时除外）。使用上要知道：

- 上游一轮只在结束时给正文，所以每一步工具调用要等上游这一轮跑完（简单步骤十几秒）才出现；
- 同一 Claude Code 会话里的主对话、子代理、各种旁路请求（输入建议、会话标题等）各接各的上游会话，
  旁路请求插进主对话的上游会话时，网关会让上游忽略它们，主对话的记忆不受影响；
- 上游偶尔写出不合法的调用块时，Claude Code 里会出现一条 `oaiprism_invalid_tool_call` 的报错，
  这是网关在让上游重发，下一步会自动接上；
- 图片：粘贴进对话的图片、用 Read 读到的本地图片都会传给上游，模型能看到图的内容。

**Codex CLI**（`~/.codex/config.toml`）

```toml
model_provider = "oaiprism"
model = "gpt-6.1-sol"
model_context_window = 1000000

[model_providers.oaiprism]
name = "oaiprism"
wire_api = "responses"
requires_openai_auth = false
base_url = "http://127.0.0.1:8787/v1"
experimental_bearer_token = "<你的 Key>"
```

**思考过程**：上游模型以智能体方式干活 —— 先思考、调工具（检索、在沙箱里写文件），最后才一次性给出
回答。干活期间每一步的思考摘要（英文，几句话）和工具调用边做边到，网关收到就转给客户端，工具调用显示成
一行"→ 调用工具 `apply_patch`"。简单问题没有中间步骤，思考摘要和答案一起到；推理强度为 low 时通常没有
摘要，其它强度也不保证每轮都有。网关按各协议的标准形状转给客户端：

| 客户端 | 形状 | 显示 |
|---|---|---|
| Chat 接口 / Dashboard 调试台 | `reasoning_content` | 调试台消息上方的"思考过程" |
| Responses 接口 / Codex | 排在最前的 `reasoning` 条目（`summary_text`） | Codex 的 thinking 条目 |
| Anthropic 接口 / Claude Code | `thinking` 块（请求开了 `thinking` 且 `display` 不是 `omitted` 时） | Claude Code 的 Thinking |

客户端下一轮把这些思考原样带回来时，网关不会把它们发给上游。

**长任务**：复杂任务（一大张多约束的 SVG 插画、多文件改动）一轮跑半小时以上很正常，正文要到最后才有。
`facade.max_poll_timeout`（默认 15 分钟）是"上游毫无进展"的最长等待，来了新的思考摘要或工具调用就重新
计时；`facade.max_run_timeout`（默认 2 小时）是一轮的总上限。非流式请求另受 `facade.sync_timeout` 约束，
长任务请用流式。

**成品写在回答里，不写进上游沙箱**：上游沙箱对客户端是黑盒，写进去的文件用户拿不到。网关按客户端的能力
提示上游：
- Codex（工具桥）：文件一律通过 Codex 在本机执行的命令写到本地，禁止用沙箱工具写文件；
- Claude Code（工具桥）：文件一律通过 Claude Code 的 Write / Edit 写到本地；上游仍写进沙箱时，网关把
  新文件转成 Write、修改转成 Edit 交给 Claude Code；
- 声明了文件工具的 Chat 客户端：沙箱里写的文件转成它的写文件工具调用；
- 其余客户端（Dashboard 调试台、普通聊天客户端、没声明工具的 Anthropic 客户端）：要求上游把文件内容直接写在回答的代码块里
  （svg / html 在调试台里直接显示成图），不在沙箱里写文件、跑脚本。实测一张多约束 SVG 插画从 20 分钟
  （沙箱里写文件、渲染检查）降到 9 分钟，成品直接在回答里。

上游偶尔仍把成品写进沙箱时，没声明工具的 Chat 客户端会在回答后面多一节"生成的文件"兜底：每个文件一个
代码块，修改过的文件给出改动，单个超过 1 MB 的只列文件名。

Codex 每轮回传完整历史，网关只把上游还没见过的部分发过去，会话历史保存在上游（见
[架构与原理](架构与原理.md#原生续接)）。上游没有测到上限：同一会话灌到 1546 万 tokens（官方公布的上下文
是 100 万），最早的内容仍逐字答对 —— 长会话由上游自己管理，网关不替它压缩、也不主动换会话。`model_context_window` 因此只决定 Codex 自己什么时候压缩它本地那份历史 —— 压缩时网关让上游在
同一个会话里写摘要，压缩后继续用这个会话，上游那边的记忆不受影响。`1000000` 是个够用又不让 Codex 每轮
回传的历史过大的值，可按需调大。
你本机的 AGENTS.md（全局与项目）会随请求带上，并声明上游沙箱自带的 Prism AGENTS.md 不适用
（见[架构与原理](架构与原理.md#上游提示词分层)）。

**可用模型**（以 `GET /v1/models` 为准）：

| 模型 | 推理强度变体 |
|---|---|
| `gpt-6.1-sol`（默认） | `-low` / `-high` / `-xhigh` |
| `gpt-6-luna` | `-high` / `-xhigh` |
| `gpt-5.6-sol` | `-low` / `-high` / `-xhigh` |
| `gpt-5.6-terra` | `-high` / `-xhigh` |

映射表在 `facade.models`，可按需增删。

## 端点一览

**推理门面**（另有 `/chat/completions`、`/responses`、`/models` 无前缀别名）：

| 端点 | 说明 |
|---|---|
| `POST /v1/chat/completions` | Chat Completions（流式/非流式、图片输入） |
| `POST /v1/completions` | 老式 Completions，内部转 chat |
| `POST /v1/responses` | Responses API（新版 SDK / Codex CLI 首选，含工具桥） |
| `POST /v1/messages` | Anthropic Messages（完整流式事件序列） |
| `GET /v1/models`、`GET /v1/models/{id}` | 模型清单 |
| `POST /v1/embeddings`、`POST /v1/images/generations` | 明确返回 501：上游只提供对话式补全 |

**运维与探针**：`GET /healthz`（存活，不查下游）、`GET /readyz`（无可用账号时 503）、
`GET /metrics`（Prometheus 文本）、`GET /dashboard/`。

**管理 API**（`/admin/*`，权限见上文）：

| 端点 | 说明 |
|---|---|
| `GET/POST /admin/accounts`、`PUT/DELETE /admin/accounts/{id}` | 账号查询与增删改（不返回凭据内容） |
| `POST /admin/accounts/{id}/refresh`、`POST /admin/reload` | 强制刷新 token、从 SQLite 重建账号池 |
| `POST /admin/oauth/begin`、`GET /admin/oauth/status`、`POST /admin/oauth/exchange` | 官方 OAuth 授权导入（PKCE） |
| `GET /admin/requests`、`GET /admin/statistics`、`GET /admin/stats` | 请求流水、调用统计、运行态 |
| `GET/POST /admin/apikeys`、`DELETE /admin/apikeys/{key}` | API Key 管理 |
| `/admin/chat/sessions…` | Dashboard 调试台会话持久化 |
| `POST /admin/login`、`GET /admin/me` | 管理员登录与状态 |

**原样反代**：`/prism/*` 按 `raw_proxy.allow_paths` 白名单（按路径段匹配）转发到上游，注入账号池凭据。

## 请求级控制头

| 头 | 作用 |
|---|---|
| `X-Oaiprism-Session` | 会话身份：决定账号粘性、项目复用与续接哪个上游会话 |
| `X-Oaiprism-Account` | 指定账号（调试用） |
| `X-Oaiprism-Project` | 指定上游项目 ID |
| `X-Oaiprism-Model` / `X-Oaiprism-Effort` | 覆盖模型名 / 推理强度 |
| `X-Local-Workspace` | 把上游产物写到**网关所在机器**的目录；默认关闭，需开启 `facade.local_workspace_write` 且仅限本机请求 |

## 运维与配置

```bash
./oaiprism.exe probe -config configs/config.yaml                            # 检查账号是否可用
curl -H "Authorization: Bearer $KEY" http://127.0.0.1:8787/admin/accounts   # 账号池运行态
curl -s http://127.0.0.1:8787/metrics | grep -E 'first_delta|facade_runs|poll_rounds'
```

常用配置（完整说明见 [`configs/config.example.yaml`](../configs/config.example.yaml)）：

| 配置 | 说明 |
|---|---|
| `upstream.sentinel_profile` | 签 Sentinel 令牌时扮演的浏览器指纹（JSON 路径）；留空用内置指纹 |
| `facade.api_keys` | 配置文件 Key（同时具备管理权限）；也可用 `OAI_PRISM_API_KEYS` |
| `server.admin_password` | Dashboard 管理员密码；也可用 `OAI_PRISM_ADMIN_PASSWORD` |
| `facade.local_workspace_write` | 是否允许 `X-Local-Workspace` 写网关本机目录（默认 `false`） |
| `facade.platform_notice` | 是否在非 Codex 请求前加声明，作废上游注入的 Prism AGENTS.md（默认 `true`） |
| `facade.default_system_prompt` | 调用方没带 system 时的兜底提示（默认是不带平台人设的中性提示） |
| `facade.max_prompt_bytes` | 发往上游的单条提示词字节上限（默认 98304，即 96 KiB；上游约 100 KiB）。只约束单轮内容：新建上游会话时历史放不下就分段补种；本轮内容本身就超出时回 `context_length_exceeded`，不发上游。`-1` 关闭 |
| `facade.reuse_project` / `project_ttl` | 项目复用 |
| `facade.use_sandbox` / `sandbox_ready_wait` | 沙箱前置流程 |
| `pool.strategy` / `sticky_ttl` / `max_wait` | 账号调度、粘性、全池冷却时的最长等待 |
| `raw_proxy.allow_paths` | 原样反代白名单 |

关键指标：`oaiprism_facade_first_delta_seconds` 直接衡量首字延迟。

## 部署与回滚

单二进制 + `web/dist` 静态资源，发布即替换文件后重启网关（`make build-linux`
产出 `bin/oaiprism-linux-amd64`）。没有别的进程要一起发布或重启。

SQLite（`secrets/accounts.db`）向前兼容，回滚只需换回上一版二进制。
